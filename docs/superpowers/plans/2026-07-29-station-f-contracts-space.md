# Station F — Contracts + Space Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the world geometry and physics. Nested coordinates + real distance, real move duration (distance ÷ speed, tension-budget-blocked), ObjectRelocated volume-blocking and eager recursive encumbrance, Portal traversal as an accessibility gate, and mint validation + persistence — so "I approach the bar and order a beer" decomposes and resolves as two real actions, the locked cellar hatch actually stops you, and grabbing the black-hole pack pins you where you stand.

**Architecture:** Every deliverable is the engine acquiring a *reader* for vocabulary Station E's foundations seeded but nothing consumed. Blocker-only throughout (contract arithmetic BLOCKS impossibilities, never awards success — FINAL-action-contracts §0). Measurements in state, verdicts computed at ask-time (no `has_`/`can_`/`is_allowed_` columns, ever). SQL owns the deterministic arithmetic (distance, duration, volume, weight); Go orchestrates and consumes the tension budget across the chain; the verdict stage gains the mint's three nets. Location goes from flat (scene id only) to nested (coordinate-in-parent + actor coordinate-in-scene) without an LLM in the distance path.

**Tech Stack:** Go (`core/api`, package main), PostgreSQL (dbmate migrations + pgTAP `core/db/tests/`), existing bridge/driver registry. Units fixed system-wide: **meters, seconds, kilograms** (speeds m/s).

## Global Constraints (the fence — every task implicitly includes these)

- **Scope = FINAL-action-contracts.md, exactly.** "If a computation is not in this document, the engine cannot do it." Anything not in §1–§8 routes to the resolution LLM. Do not add engine powers beyond the contract table.
- **Blocker-only (founder-locked §0).** The gate and contract arithmetic exist to BLOCK impossibilities. Success = the absence of a blocker. Never read "the contract computes the move" as "the move succeeds" — the world still gets its word first (world-first), and opposition is always the resolution LLM, never arithmetic.
- **Measurements, not verdicts (founder-locked §0).** Every persisted property is a measurement (`max_room`, `occupied_room`, `max_load`, `carried_weight`, `base_speed`, `coordinates`). Verdicts (`has-room`, `within-load`, `fits-time`) are arithmetic run at ask-time, never stored. Nouns for state, verbs for checks. Statuses (`encumbered`) ARE legal state — conditions with provenance and a lifetime, inputs to arithmetic, never pre-cached answers.
- **The two-tier wall (§5.2).** Tier-1 (engine-known, closed set in `core/api/tier1.go`) is read by engine checks and strictly validated. Tier-2 is LLM-invented, carried in payloads, NEVER read by the engine. The engine may only read attributes named in the contract. Rule B: the LLM may not write Tier-1 by invention — `locked`/`open`/`connects`/`size`/`weight`/coordinates change only through committed, shape-validated rulings.
- **Units fixed:** meters, seconds, kilograms. A mint in other units is invalid data (§8).
- **Mint validation = shape + derivable bounds only (§8).** No plausibility bounds ("is 400 m/s too fast?"). Trust comes from the three nets: a mint only happens inside an adjudicated ruling past the reality check; blast radius is one logged row with provenance; every mint is audit-trailed.
- **D-1:** only the SQL commit path writes canon. Go orchestrates; SQL commits and computes the deterministic arithmetic. Append-only canon.
- **Accepted imprecisions — do NOT "fix" (they are founder-locked closed decisions):** (a) cross-level distance ignores the walk-to-the-exit-point part — fixing it needs exit-point inference = an LLM = forbidden on this path (§3); (b) Portal is accessibility, NOT geometry — no exit points, no doorway positions, no distance contribution (§5.3); (c) encumbrance slowing (weight → speed penalty beyond the −100% encumbered stop) is explicitly NOT built (§4); (d) throwing has no contract → resolution LLM (§4); (e) over-budget move = REJECT, never clock-jump except under `none` tension (§2). An agent who "improves" any of these is reopening a closed decision.
- **Harness:** dbmate `-- migrate:up`/`-- migrate:down`; `schema.sql` regenerated by `make migrate`, never hand-edited; every migration paired with the regenerated `schema.sql` in the same commit (`make schema-check` is a git-diff exit-code guard). pgTAP house style (`plan(N)`/`finish()`, fresh labels, `BEGIN…ROLLBACK`, self-contained). Go from `core/api/`. New pgTAP files continue at `110_`+; migrations continue after `20260726100001_display_name_naming_reach.sql`.
- **Battery per task:** `make reset && make test` · `cd core/api && go test -count=1 ./...` (re-run TestRunBeat/TestBeat for stability) · `make schema-check` · `make schema-contract`.
- **TDD failing-test-first; one commit per task minimum; plain comments; every new rule in code ships with its worked example (the contract doc's own discipline). One station = one PR.**
- **Station-D incident lesson (binding):** every commit names its exact files in `git add` — never a broad `git add .`/`-A`.

## Flagged plan-level decisions (grounded in the spec; founder may veto)

1. **One tick = one second.** The engine's `in_world_tick`/duration `bigint` is seconds. `fn_move_duration` returns seconds; tension budgets are seconds; no conversion layer. Grounded: the stub returns `5`, frantic budget is `5 s`, and the foundations map ties them. Stated once in code; no unit drift.
2. **Coordinates + parent edge live in the existing `attrs` JSONB, as Tier-1 measurements.** Actor position-within-scene → `actor_state.attrs.coordinates` (registered Tier-1 `coordinates:object`); a location's coordinate-within-parent → `location_state.attrs.coordinates`, and its parent → a new Tier-1 name `parent_location_id` (string). This follows the shipped `attrs`-JSONB measurement pattern (the Tier-1-DDL-vs-JSONB fork stays open per the foundations' flagged decision; F does not resolve it, it continues the JSONB convention with running-code evidence). Coordinate shape: `{"x":<number>,"y":<number>}` in meters within the parent's local frame; the parent's `extent` (`{"w":<number>,"h":<number>}`) bounds mint validation.
3. **`volume` is DERIVED, never stored.** `volume(size) = 4^(size-1)` computed at ask-time from `size` (§4). It does NOT enter `tier1Registry` — a stored volume would be a cached measurement of a measurement, and the room-check reads `size`. This resolves recon's "missing name": nothing is missing.
4. **F6 includes mint PERSISTENCE, not just validation.** Today the `Mints` ruling slot is decoded but inert — no committed path inserts a movement type, status modifier, or typed artifact. F2/F4 arithmetic is only exercised against the two seeded rows until real minting works. F6 therefore (a) validates the three nets at the verdict stage, (b) enforces mint-ordering, and (c) persists accepted mints into `movement_type`/`status_modifier`/`entity_registry`+state, audit-trailed to the ruling event. This is the honest scope of "mint validators" given the inert slot.
5. **The seed's coordinates are hand-authored — a sanctioned test artifact.** §3 says coordinates are LLM-minted, never hand-authored, and "the hand-placed seed world is a test artifact, not the pattern." The Drowned Lantern seed gets hand-authored coordinates + a container instance under exactly that license (the same license the whole seed already holds). Production worlds mint coordinates via F6.
6. **`fn_move_duration` keeps its `(uuid,uuid,uuid)→bigint` signature.** The legacy SQL `apply_beat` path still calls it and is still tested; F2 changes its BODY (flat-5 → real arithmetic), not its signature, so `apply_beat` keeps working and its tests absorb the new real durations. The live path is the Go orchestrator; `apply_beat` is legacy-but-green.
7. **Actor active statuses get a real representation (F2), written eagerly by F4.** `effective_speed` needs to know which modifier statuses an actor currently has. F2 introduces `actor_state.attrs.statuses` (array of `status_type_id`) as the read model; `effective_speed` intersects it with `status_modifier` rows. F4's eager rule writes/clears `encumbered` in that array in the same commit as the carry change. `encumbered` present → −100% → speed 0 → move blocked, purely by arithmetic (no special "tied" rule).
