**Goal:** Make the engine compute the facts and feed them to every LLM seat, add a read-only question path, and surface a behind-the-curtain reasoning trace — so no seat reasons ungrounded, the player can ask "how long to the bar?" and get the real answer, and the math is visible while playing.

**Architecture:** One deterministic `fn_fact_sheet` computes action-scoped physics facts (distance/duration/reachability/weight/lock/contents) over the same involved entities `gather_slice` already pulls, in a truth-side flavor (for the referee) and a perception-scoped flavor (for the character-mind seats). It rides into the cognition, resolve, and narrate prompts. The decomposer gains a read-only `QUERY` element whose answer is the perceived fact sheet, phrased by the narrator. A `BeatTrace` threaded through the orchestrator emits a `reasoning_log` in debug mode, rendered as a play-page panel.

**Tech Stack:** Go (`core/api`, package main), PostgreSQL (dbmate migrations + pgTAP), JSON Schema draft-07, existing bridge/driver registry; React + Vite (dreamchat-frontend-play) for the trace panel.

### Task 1: `fn_fact_sheet` — the deterministic fact computation (Unit 1 spine)

**Files:**
- Create: `core/db/migrations/20260730100001_fact_sheet.sql`
- Modify: `core/db/schema.sql` (via `make migrate`)
- Test: `core/db/tests/119_fact_sheet_test.sql`

**Interfaces:**
- Produces (consumed by Tasks 2, 3, 5): `fn_fact_sheet(p_world_id uuid, p_viewer uuid, p_involved uuid[], p_truth_side boolean) RETURNS jsonb` — an object `{"budget_remaining": null, "targets": [ {id, kind, name, distance_m, move_duration_s, reachable, open, locked, weight_kg, volume, would_encumber, contents} ... ]}`, one `targets` entry per id in `p_involved` EXCEPT the viewer itself. `budget_remaining` is always JSON null here (the orchestrator fills it — it is beat state, not an entity fact). Per target, relative to `p_viewer`:
  - `distance_m` = `fn_distance(p_world_id, p_viewer, target)`; `move_duration_s` = `fn_move_duration_actor(p_world_id, p_viewer, target)`; `reachable` = same-scene OR `fn_portal_permits(viewer_scene, target_scene)`.
  - Portal target (`attrs ? 'connects'`): `open`, `locked` from Tier-1 attrs; else null.
  - Object with `attrs ? 'size'`: `weight_kg` = `fn_effective_weight(world, target)`, `volume` = `fn_volume((attrs->>'size')::int)`, `would_encumber` = `weight_kg > (viewer max_load)`; else null.
  - Container (`attrs ? 'max_room'`): `contents` = ids with `attrs->>'contained_by' = target`. **PERCEPTION GATE:** in the perceived flavor (`p_truth_side=false`), `contents` is the JSON literal `null` UNLESS the container's `attrs->>'open' = 'true'`; in the truth flavor it is always the id array. This is the one field that differs by flavor in v1.
- Consumes: `fn_distance`, `fn_move_duration_actor`, `fn_portal_permits`, `fn_effective_weight`, `fn_volume` (all Station F). LANGUAGE sql STABLE. No LLM, no seat.
